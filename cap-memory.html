能力 / 长期记忆

Organizational memory / 能力

长期记忆

让组织做过的事，成为下一次任务的起点。

定义Definition

智能体不是每次从零开始，
它记得上次做过什么。

决策 / Decision 经验 / Experience 口径 / Registry

Problem / 问题

经验留在人身上，组织就会反复付学费。

同一个任务换一个人做，就像重新启动一次系统：背景要找、口径要问、结论要再证明一遍。

01

新人离职带走经验

做过什么判断、为什么这样做、后来结果如何，如果没有被记录，就只能靠下一个人重新摸索。

02

同一个问题反复问

缺少可检索的历史，每次任务都从零开始。时间花在重新理解问题，而不是继续推进答案。

03

同一份口径算出来不一样

指标定义散落在个人表格和聊天记录里，部门各自维护一套算法，最后只能在对数会上寻找共识。

How it works / 怎么做

把做过的事，变成下一次的起点。

长期记忆不是把所有内容堆起来，而是让相关内容在任务发生时，被准确地找回来。

01 / WRITE

决策与经验写入知识库

把任务背景、判断依据、处理动作与结果留下来，形成下一次可以继续使用的上下文。

决策记录 · 处理经验
02 / RECALL

下次任务自动调出相关历史

智能体先找回相似任务、已有结论与处理路径，再开始新的判断，而不是重新问一遍。

相似任务 · 历史结论
03 / UNIFY

口径按注册表统一

指标定义、负责人和适用范围由注册表管理，让不同部门的答案从同一个定义出发。

定义 · 负责人 · 生效范围
Registry principle / 注册表原则

记忆负责保留做过的事；注册表负责说明事情应该按什么口径被理解。两者一起，才构成可复用的组织上下文。

Real scenarios / 真实场景

场景不新，难的是每次都得到同一答案。

长期记忆的价值，不在存储本身，而在下一次任务开始得更快、判断更稳。

01

门店数据查询口径统一

同一个门店指标，从总部到区域都沿着注册表里的定义计算，减少会议里对不齐的数。

02

异常处理记录可追溯

问题如何判断、采取了什么动作、由谁确认，都留下可回看的过程，而不是只留下最终结果。

03

部门经验在人员变动后仍在

流程与判断不再只存在某个人的脑中。交接从重新讲一遍，变成直接调用已有历史。

Boundary / 边界

记忆需要维护，脏数据会进去，所以要有人管口径。

长期记忆不是自动正确。它是一套需要制度、负责人和持续维护的内容系统。

01

记忆需要维护

过期、冲突和失效的经验必须被清理与更新，否则历史会反过来误导当下。

02

脏数据会进去

错误前提一旦被写入知识库，就会被下一次任务继续沿用。入口需要校验，过程需要留痕。

03

要有人管口径

每个关键指标都应有明确负责人、定义和适用范围。统一不是一次性动作，而是持续治理。
